VULNERABILITY DEEP DIVE

CSRF & API Vulnerability Audit

Cross-Site Request Forgery (CSRF) forces end users to execute unwanted actions on web applications in which they are currently authenticated. Coupled with API security flaws, attackers can bypass security controls and alter sensitive data seamlessly.

1. Key CSRF & API Vectors We Test

A. Cross-Site Request Forgery (CSRF)

Auditing state-changing POST/PUT requests for anti-CSRF token verification.

  • Missing CSRF Tokens: Executing actions (email/password change) without anti-forgery tokens.
  • Token Validation Bypasses: Testing empty tokens, duplicate tokens, or static tokens across different user sessions.

B. REST & GraphQL API Flaws

Inspecting modern API endpoints for authorization and data exposure bugs.

  • Broken Object Level Authorization (BOLA): Testing access to private API objects via modified JSON payloads.
  • Mass Assignment: Injecting administrative parameters (e.g., `"is_admin": true`) in user update endpoints.

C. Insecure CORS & JWT Implementation

  • JWT Token Vulnerabilities: Testing 'none' algorithm bypasses, weak HMAC secret keys, and missing expiry checks.

2. Mitigation & Hardening Rules

  • Anti-CSRF Tokens: Use unique, cryptographically secure synchronizer tokens for state-changing requests.
  • SameSite Cookie Attribute: Set `SameSite=Strict` or `SameSite=Lax` on all session management cookies.
  • Strict API Authorization: Implement object-level and function-level access control on every single API route.
  • JSON Schema Validation: Validate incoming request bodies against strict schemas to prevent mass assignment.

3. Audit Tools & Methodology

We use Burp Suite CSRF Generator, Postman API Security Testing, Kiterunner for API endpoint discovery, and jwt_tool for token manipulation assessments.
