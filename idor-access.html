VULNERABILITY DEEP DIVE

IDOR & Broken Access Control Testing

Insecure Direct Object References (IDOR) and Access Control flaws occur when applications fail to properly verify whether an authenticated user has permission to view, edit, or delete specific system objects or administrative routes.

1. Types of Access Control Flaws We Test

A. Horizontal Privilege Escalation (IDOR)

Manipulating object identifiers to access records belonging to another user with the same role.

  • Parameter Tampering: Changing IDs in URL or API requests (`?account_id=1001` to `1002`).
  • Private Data Exposure: Downloading other users' private PDFs, invoices, or personal documents.

B. Vertical Privilege Escalation

Bypassing role authorization to perform actions reserved for higher privilege levels (e.g., Admins).

  • Unrestricted Admin Endpoints: Accessing paths like `/admin/delete-user` as a regular guest.
  • Header Manipulation: Tampering with role parameters (e.g. `role: admin` or `is_admin: true`).

C. CORS & Origin Misconfigurations

  • Over-Permissive Origin Policies: Exploiting `Access-Control-Allow-Origin: *` with credentials enabled to extract sensitive data.

2. Prevention & Remediation Guidelines

  • Server-Side Authorization Checks: Enforce strict access control logic on every single API endpoint and request.
  • Use Indirect Object References: Replace sequential numeric IDs (`?id=5`) with unpredictable cryptographic GUIDs/UUIDs.
  • Deny by Default: Block access to all routes unless explicitly permitted for a specific role.
  • Disable Directory Browsing: Ensure web servers do not list directory files or backup folders publicly.

3. Security Assessment Tools

We utilize specialized extension plugins like Burp Suite Autorize, Autorize Matrix, Postman API Auditor, and manual dual-account differential testing to catch all access control bugs.
