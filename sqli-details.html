SQL Injection (SQLi) Audit & Prevention

SQL Injection occurs when malicious SQL queries are injected into data input fields. This allows attackers to bypass authentication, access, modify, or delete sensitive database contents, and sometimes gain full control of the host server.

1. Types of SQL Injection We Test For

A. In-Band SQLi (Classic)

The attacker uses the same channel of communication to launch the attack and gather results.

  • Error-Based SQLi: Forces the database to generate error messages revealing sensitive structure details.
  • Union-Based SQLi: Uses the UNION operator to combine malicious query results with original database output.

B. Inferential SQLi (Blind SQLi)

No data is directly transferred to the screen; the attacker infers database structure by sending true/false payloads.

  • Boolean-Based Blind: Evaluates application responses (HTTP status or content change) based on TRUE/FALSE conditions.
  • Time-Based Blind: Pauses database execution (e.g., SLEEP commands) to infer valid SQL queries based on response times.

C. Out-of-Band SQLi & Second-Order SQLi

  • Out-of-Band SQLi: Executed when results cannot be seen directly, forcing DNS or HTTP requests to controlled servers.
  • Second-Order SQLi: Malicious input is stored safely first, but executed during a secondary background database action.

2. Prevention & Remediation Guidance

  • Parameterized Queries (Prepared Statements): Completely separates code from data so inputs cannot alter SQL logic.
  • Stored Procedures: Encapsulates queries safely on the database server using strongly-typed input variables.
  • Allow-List Input Validation: Validates data types, string length, and pattern matches before processing queries.
  • Principle of Least Privilege: Restricts database user accounts to read-only or strictly necessary table permissions.

3. Security Testing Tools Used

Our penetration testing team uses industry-standard toolkits including SQLmap (automated detection), Burp Suite Professional (request interception & payload analysis), OWASP ZAP, and custom Python exploitation scripts to verify zero false positives.
